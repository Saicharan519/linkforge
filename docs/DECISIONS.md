## P0.5 decisions (2026-11-05) — gaps the specs were silent on
Made under the user's delegation ("decide on your own"). Each is reflected in `docs/openapi.skeleton.yaml`. Challenge any of them before P1/P2 uses it.

| # | Decision | Why |
|---|---|---|
| D23 | Status codes and bodies: `register` 201 → User; `login` 200 → User and sets `lf_session` + `lf_csrf`; `logout` 204; `change-password` 204; `DELETE` link / api-key 204; `POST /links` 201 → Link; `POST /api-keys` 201 → ApiKeyCreated (plaintext `key` shown once) | ARCH §4 gave only some codes |
| D24 | `User` = `{id, email, created_at}` | Minimal; nothing sensitive |
| D25 | The `Origin` check also applies to unauthenticated `POST /auth/register` and `/auth/login` (login-CSRF defence). No CSRF token is needed there because no `lf_csrf` cookie exists yet | A cross-site form could otherwise log a victim into the attacker's account |
| D26 | If an `X-API-Key` header is present it is used and cookies are ignored (no CSRF check). An invalid key is 401 even if a valid session cookie is also sent | Browsers cannot set that header cross-site (we enable no CORS), so no CSRF bypass; precedence must be deterministic |
| D27 | Analytics `range` accepts `7d|30d|90d`, default `30d`, anything else → 422. `/analytics/overview` accepts the same, default `30d` | PRD fixes 30d for the overview but the shared enum is additive-safe |
| D28 | Analytics item shapes: `referrers[{host, clicks}]` (top 10; empty referrer reported as host `(direct)`), `devices[{device_type, clicks}]`, `browsers[{browser, clicks}]` (top 10), overview `top_links[{id, code, title, clicks}]` (top 5 by clicks in range) | ARCH §4 listed only the array names |
| D29 | `device_type` ∈ `desktop|mobile|tablet|other` | Needed for the device split chart |
| D30 | Machine error codes in `{"error":{"code","message","details"}}`: `validation_error`(422), `unauthorized`(401), `invalid_credentials`(401), `csrf_failed`(403, token or Origin), `not_found`(404, and 404 on the public host), `gone`(410), `alias_taken`(409), `email_taken`(409), `rate_limited`(429, with `Retry-After`), `unavailable`(503), `internal_error`(500). For 422, `details` = list of `{field, message}` | The frontend renders field errors from the API's 422 body (frontend/CLAUDE.md) |
| D31 | `GET /healthz` → 200 `{"status":"ok"}`. `GET /readyz` → 200 `{"status":"ok","postgres":"ok","redis":"ok|degraded"}`; Postgres down → 503 `{"status":"unavailable","postgres":"down","redis":"..."}` | backend/CLAUDE.md only said `{"redis":"degraded"}` |
| D32 | A 410 (expired) response is NOT cached in Redis; each hit reads Postgres. Accepted for v1 (low volume); revisit only if k6 shows it matters | ARCH §2.1 caches only 404 (neg) and active links; adding a `gone:` key would be new design |
| D33 | A random code that equals a reserved word (case-insensitive) is rejected and regenerated in the same retry loop | Reserved list includes 7-char words (`healthz`, `metrics`) |
| D34 | `PATCH expires_at` must also be in the future when non-null. A user with `is_active=false` cannot log in (generic 401). `updated_at` is set by the service on every PATCH. `HEAD /{code}` passes the redirect limiter like `GET` | Fills gaps; keeps the generic-401 rule |
| D35 | Field limits: link `title` ≤ 200 chars, API key `name` 1–64 chars | PRD gave none |

## P1 decisions (2026-11-05)

| # | Decision | Why |
|---|---|---|
| D36 | `TEST_DATABASE_URL` (new env var) points the test suite at a separate DB (`linkforge_test`); tests never touch the dev DB. Compose uses throwaway local credentials as defaults inside `docker-compose.yml` (overridable via a gitignored `.env`) and publishes Postgres/Redis on `127.0.0.1` only. (`.env.example` added 2026-11-06 once the `.env*` deny rules were relaxed; it only lists the compose variables, all optional) | Integration tests need a real but isolated DB; ARCH §9.1 had no test setting |
| D37 | Temporary dev user: one dependency `get_current_user` that ensures a fixed dev user exists; only usable when `ENV != prod`. P2.6 deletes it; a test marked to fail once real auth lands guards against forgetting | P1 needs an owner for links before auth exists |
| D38 | P1 `/readyz` returns `{"status","postgres"}` only. The `redis` field (D31) is added in P2.1 when a Redis client exists; reporting Redis health before then would be a lie | Contract is additive |
| D39 | DB connect timeout is a code constant (3 s), not an env var | Avoids inventing config for a readiness detail |
| D40 | Compose, the test-DB-creation fixture, the migrate-once fixture and the truncate-between-tests fixture all land by P1.2 (not P1.6) because the first real-Postgres tests need them; P1.6 is therefore just a review/polish pass | Order of work, not scope |
| D41 | Schema readings where ARCH §3 was silent: `created_at`/`updated_at` are NOT NULL with `now()` defaults; `links.user_id` and `api_keys.user_id` are NOT NULL; constraint/index names follow a fixed naming convention (`pk_`, `fk_`, `uq_`, `ix_`); `alembic check` runs as a test so models and migration cannot drift | The API always returns these fields; ownerless rows are meaningless; stable names keep migrations reviewable |
| D43 | URL validation is strict beyond the PRD minimum: reject any whitespace/control character or backslash, embedded credentials (`user:pass@`), underscores in hostnames, numeric last labels (malformed IPs), ports outside 1–65535. The URL is validated, never rewritten or trimmed (the frontend should trim before sending). `localhost` and private IPs are allowed (we never fetch destinations). "Own short domain" = same host as `SHORT_URL_BASE`; if that base has a non-default port (local dev), only that exact host:port counts, so another local app on `localhost:3000` stays allowed | These are classic link-disguising tricks; keeps one function the single source of truth |
| D44 | Collision handling: uniqueness is decided by the `uq_links_code` constraint (not SELECT-then-INSERT). `with_unique_code(attempt)` retries up to 5× only when the violated constraint is `uq_links_code`; any other IntegrityError is re-raised. The caller's `attempt` must leave its transaction usable (savepoint or fresh session) | Races between two creators are resolved by Postgres, and unrelated bugs are not hidden by retries |
| D45 | P1.4 API details the specs left open: link `title` must be non-empty (null clears it); `expires_at` must carry a timezone (naive times → 422); unknown JSON fields on create/PATCH → 422 (`extra=forbid`, catches typos); the link `code` is immutable (PATCH with `code` → 422); search `q` ≤ 200 chars; a malformed `{id}` in a path → 422 (field `id`), an unknown/foreign one → 404; an empty PATCH body `{}` is accepted and still sets `updated_at` (D34 read literally); new machine error code `method_not_allowed` (405) added to D30 and the OpenAPI enum | Strictness on input, one error format for framework errors too |
| D46 | Redirect details: a code that could never be created (not 3–32 of `[A-Za-z0-9_-]`) is answered 404 WITHOUT querying Postgres (keeps scanners, `/favicon.ico`, NUL bytes off the DB). Any DB/driver/timeout error → 503 `unavailable`. `HEAD` is an explicit route (verified: FastAPI answers 405 for HEAD on a plain GET route) with the same status and `Location` and no body. A non-ASCII destination host is sent as punycode in `Location`. No extra cache headers are added (a 302 is not cacheable without freshness info) | Never a 500 for a bad code; correct headers for IDN links |
| D47 | Backend image (P1S.1): base `python:3.12.16-slim-trixie` pinned by tag AND sha256 digest; two stages (a builder makes the venv, the runtime copies only the venv + app + alembic); runs as numeric uid/gid 10001; one image for API and migration (command differs); exec-form CMD so uvicorn is PID 1 and handles SIGTERM; tests, dev tools and env files excluded by `.dockerignore`; local tag `linkforge-api:dev`. Verified: runs with `--read-only --cap-drop ALL --security-opt no-new-privileges`, stops in under 1 s. Known, accepted for now: `pip` stays in the runtime image (hardening candidate for P6) | Small, non-root, reproducible, and already compatible with the Kubernetes securityContext we will set |
| D48 | Placeholder frontend image (P1S.2): base `nginxinc/nginx-unprivileged:1.30-alpine-slim` pinned by tag and digest, uid 101, port 8080, static page + nginx-answered `/healthz` + SPA fallback; no `/api` proxy (the Ingress routes it). The full `-alpine` variant was rejected: Trivy found 6 to 75 fixable HIGH/CRITICAL OS-package CVEs (curl, expat, brotli...), which would fail the CI gate; `-slim` omits modules we do not use for static files and is clean. In P4/P5 a Node build stage is added in front; the runtime stage stays. |
| D49 | CI image pipeline (P1S.3): `ci.yml` builds + Trivy-scans both images on every PR (no push); `build-push.yml` on push to main CALLS `ci.yml` (reusable workflow, so `ci.yml` has no `push: main` trigger and CI runs once per merge), then per image: build, Trivy gate, push to public GHCR as `ghcr.io/<owner lowercase>/linkforge-{api,frontend}:sha-<7>`, then ONE job commits the tag into `linkforge-gitops` `envs/kind/values.yaml` using a fine-grained PAT (`GITOPS_TOKEN`, that repo only, Contents RW). Tags are the commit, never `latest`. Plain `docker build/push` instead of docker/* actions (fewer third-party pins; layer caching is not worth it at ~35 s builds). Trivy install is a local composite action, pinned by version + sha256. Bump edits lines marked `# ci:api-tag` / `# ci:frontend-tag` with sed (fails loudly if a marker is missing; no commit when nothing changed; push retried with rebase). `build-push` concurrency is serialized, never cancelled. If the bump fails after the push, the image is simply unused and the next merge repairs it. |
